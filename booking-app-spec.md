# Техническое задание: демо-приложение бронирования столов кинобара «Персонажи»

> Этот документ — полный и самодостаточный бриф для исполнительной модели. Он заменяет ранний черновик `personages-booking-demo.md`. Всё, что нужно для построения приложения, описано ниже: цвета, шрифты, тексты экранов, координаты столов, состояния, анимации, мок-данные и критерии приёмки. Вопросов к заказчику возникать не должно — при неопределённости следуй разделу «Допущения».

---

## 1. О проекте

**«Персонажи» (PERSONAGES)** — атмосферный кинобар в центре Минска (ул. Карла Маркса, 33). Концепция построена вокруг кино: интерьер с мотивами классического Голливуда, нуара и берлинского стиля; кинотеатральные кресла и проектор; витраж со сценой из «Форреста Гампа»; ковры в духе отеля «Оверлук» из «Сияния»; авторские коктейли по мотивам фильмов; регулярные киновечера и тематические вечеринки.

**Задача:** создать демо-версию мобильного веб-приложения для бронирования столов. Приложение одновременно:

1. Знакомит гостя с баром (атмосфера, концепция, адрес, афиша событий).
2. Проводит гостя по полному сценарию бронирования: параметры → выбор стола на интерактивном плане зала → контакты → подтверждение в виде кинобилета.

**Админ-панель в демо НЕ реализуется**, но архитектура обязана быть готова к её добавлению (см. раздел 10).

**Главное требование:** приложение должно выглядеть как продолжение айдентики бара — тот же визуальный код, что и афиши/Instagram заведения. Не «ещё одно приложение для брони», а маленький интерактивный киноплакат.

## 2. Формат устройства (важно)

- Приложение **mobile-first**, эталонный экран — **iPhone: 390 × 844 px**, вертикальная ориентация, учёт safe-area (верх/низ).
- Все экраны — вертикальный скролл внутри «экрана телефона».
- **На десктопе** приложение показывается в центрированной рамке телефона (390×844, скругление ~40px, тонкая золотая обводка 1px `#D7CC8F` с прозрачностью 30%), а пространство вокруг — тёмный фон `#150101` с лёгким размытием/виньеткой. Рамка телефона — декоративная, внутри всё работает как мобильное приложение.
- Touch-цели ≥ 44×44 px. Никаких hover-only взаимодействий.

### 3.2. Типографика

Google Fonts, подключить оба семейства:

- **Заголовки, логотип, цифры билета:** `Playfair Display` (fallback: `Cinzel`, далее `Georgia, serif`). Характер — классический кинематографичный serif, как на афишах бара.
- **Основной текст, формы, кнопки:** `Inter` (fallback: `Manrope`, `system-ui`).

Правила:

- Логотип `ПЕРСОНАЖИ` (кириллицей): Playfair Display, uppercase, letter-spacing `0.35em`, цвет `--accent`.
- Заголовки экранов: Playfair Display, 24–28px, `--accent`.
- Заголовки афиш (TARANTINO NIGHT и т.п.): uppercase, letter-spacing `0.15em`.
- Тело: Inter, 15–16px, line-height 1.55, `--accent` с прозрачностью 85–100%.
- Микроподписи (подсказки, правила): Inter, 12–13px, `--accent-dim`.

### 3.3. Формы и декор

- Радиусы: карточки 16px, кнопки 12px (или pill для мелких чипов), поля ввода 12px.
- Обводки: 1px `--accent` с прозрачностью 25–40%. Никаких тяжёлых рамок.
- Тени: мягкие, тёплые (`0 8px 32px rgba(0,0,0,0.45)`), без цветных теней.
- Разделители: тонкая золотая линия 1px с прозрачностью 20%, по центру можно ромб ◆ или символ ✦ как орнамент афиши.
- Эффект киноплёнки: перфорация (ряд полукруглых вырезов) на билете и по краям карточек афиши; лёгкое зерно (noise) поверх hero-фото — через SVG-фильтр или PNG-шум с opacity 0.04–0.06.
- Иконки: Lucide, тонкие (stroke 1.5), цвет `--accent`.

### 3.4. Кнопки

- **Primary:** обводка 1px `--accent`, прозрачный фон, текст `--accent`, uppercase, letter-spacing 0.12em. Hover/tap: плавная заливка `--accent`, текст становится `--text-on-accent` (transition 200–250ms).
- **Disabled:** обводка и текст с прозрачностью 30%, без анимации.
- **Опасное/вторичное действие:** текстовая кнопка `--accent-dim`, подчёркивание при тапе.

## 4. Киношные отсылки (обязательный минимум)

Интерфейс должен быть нашпигован стильными, ненавязчивыми отсылками к кино. Обязательны все пять:

1. **Ковёр из «Сияния»** — фон плана зала использует файл `pattern.jpg` (шестиугольный узор отеля «Оверлук»). Узор приглушён: поверх него полупрозрачная заливка `#2C0404` (60–70%) или сниженная opacity текстуры, чтобы столы читались.
2. **Кинотерминология** — вместо «слот/бронь/столик» в интерфейсе: «сеанс», «зал», «место», «билет». Примеры: «Выберите сеанс», «Ваш билет», «Место №4».
3. **Обращение «Дорогие зрители»** — на экране успеха и/или в блоке правил, как в stories бара.
4. **Афиша событий** — карточки оформлены как кинопостеры бара (стиль `color-scheme.jpg`): крупный serif-заголовок, дата, время, минималистичная иллюстрация-силуэт.
5. **Билет с перфорацией** — финальный экран подтверждения выглядит как отрывной кинобилет.

Дополнительно (по желанию, не перегружая): кадрирование фото как «кадр плёнки» с перфорацией; номер брони в формате «РЯД 4 · МЕСТО 2»; прелоадер в виде кинохлопушки.

## 5. Экраны приложения

Всего 5 экранов. Навигация линейная по воронке брони, с возможностью вернуться назад. Переходы — анимированные (раздел 6).

### Экран 1. Главная (знакомство с баром)

Вертикальный скролл, секции:

**1.1. Hero (ровно 100% высоты экрана)** — блоки «О баре» и далее не видны на лендинге и появляются только при скролле.
- Фон: фото интерьера бара (заглушка — см. раздел 12), поверх градиент `linear-gradient(180deg, rgba(44,4,4,0.35), rgba(44,4,4,0.92))` и зерно плёнки.
- По центру: логотип `ПЕРСОНАЖИ` (правила из 3.2), под ним тонкая золотая линия с ромбом.
- Слоган: *«Атмосферный кинобар в центре Минска»* (Inter, `--accent-dim`).
- Ниже: *«ул. Карла Маркса, 33»* с иконкой геопозиции.
- Кнопка primary: **«Забронировать стол»** → ведёт на Экран 2.
- Индикатор скролла вниз (тонкая стрелка, мягко пульсирует).

**1.2. О баре**
- Заголовок: «О баре» или «Наша история».
- Текст (можно использовать дословно):

Кинотеатральные кресла и проектор, витраж со сценой из «Форреста Гампа», ковёр в духе отеля «Оверлук», винил с саундтреками и коктейли, названные в честь героев кино. Классический Голливуд, нуар и берлинский стиль — в центре Минска.

- Строка фактов: адрес, часы работы (заглушка: «вс–чт 16:00–01:00, пт–сб 16:00–03:00»), ссылка-заглушка на Instagram `@personages.bar`.

### Экран 2. Параметры брони («Выберите сеанс»)

- Шапка: кнопка «назад», заголовок **«Выберите сеанс»**, подзаголовок *«Стол будет ждать вас 2 часа»*.
- **Дата:** горизонтальный скролл чипов на 7 дней вперёд от сегодня. Чип: день недели (сокр., напр. «ПТ»), число, месяц. Активный — заливка `--accent`, тёмный текст.
- **Время:** сетка слотов с шагом 30 минут, 16:00–23:30 (последний слот выбирается с учётом лимита 2 часа и закрытия). Чипы-слоты; часть слотов детерминированно помечена недоступными (мок, раздел 9.3) — они приглушены и не кликабельны.
- **Гости:** stepper «− / +», диапазон 1–8, по умолчанию 2 (максимум соответствует самому большому столу — секретному залу на 8).
- **Заметка о лимите:** строка с иконкой часов: *«Дорогие зрители, бронь стола ограничена 2 часами»*.
- **Кнопка «Выбрать место»** — активна только когда выбраны дата и время. Переход на Экран 3.
- Состояние выбора (дата/время/гости) сохраняется при возврате назад.

### Экран 3. План зала («Выберите стол») — центральная фишка

- Шапка: «назад», заголовок **«Выберите стол»**, подзаголовок-подсказка: *«Нажмите на свободный стол»*.
- **План зала** — минималистичная схема по файлу `plan.png` (исходник 1152×648, план вписан по ширине экрана, aspect-ratio 1152/648). Стены удобно рисовать SVG с `viewBox="0 0 1152 648"` — координаты ниже даны в пикселях исходника.
  - Пол: текстура `pattern.jpg` (ковёр «Оверлук»), лишь слегка проглядывает через бордовое наложение `--bg-primary` с прозрачностью ~85% — узор не должен быть чётким оранжевым.
  - Стены: линии `--accent` с прозрачностью ~55–75%, толщина ~4px в координатах viewBox.
  - Главный зал: левая стена x=145, верх y=172 (с выступом барной стойки x=285–585, верх стойки y=95, скруглённые углы), правая стена x=831, низ y=555; вход — разрыв нижней стены x=640–775.
  - Секретный зал: примыкает справа (x=831–1015, y=170–430), правая стена скруглена, дверь — разрыв в левой стене (y≈300–430).
  - Подписи мелким uppercase (`--accent-dim`, letter-spacing 0.2em): **BAR** (над стойкой), **ВХОД** (у разрыва нижней стены).
- **Столы и места** — 9 позиций (координаты центра в пикселях 1152×648, в процентах — в моках раздела 9.2):

| ID | Что это | Форма | Мест | Центр (px) |
|----|---------|-------|------|-------------|
| T1 | Стол 1 | Круг | 4 | (238, 253) |
| T2 | Стол 2 | Круг | 4 | (691, 240) |
| T3 | Стол 3 | Круг | 4 | (233, 455) |
| T4 | Стол 4 | Овал горизонтальный | 4 | (475, 480) |
| B1–B4 | Барные стулья | Малые круги у стойки | 1 каждый | (330, 140), (390, 140), (455, 140), (525, 140) |
| S1 | Секретный зал | Длинный стол (пилюля) | 8 | (923, 365) |

  Барные стулья бронируются только на 1 гостя (при guests > 1 недоступны); секретный зал — на компанию до 8.

- **Состояния столов:**
  - `free` — полупрозрачная заливка `--accent` 12%, обводка 1px `--accent` 70%, номер стола внутри. Tap-эффект: лёгкое увеличение (scale 1.05).
  - `selected` — заливка `--gold-bright`, тёмный номер, мягкое пульсирующее свечение (box-shadow, 1.6s, ease-in-out, infinite).
  - `occupied` — заливка `--red-deep` 25%, обводка `--red` 40%, номер зачёркнут/приглушён, `cursor: not-allowed`, тап игнорируется (можно лёгкая встряска shake 200ms).
  - Дополнительно: если выбранное число гостей больше вместимости стола, стол визуально помечается как «мал» (иконка или приглушение) и не выбирается.
- **Bottom-sheet** при тапе на свободный стол (spring-анимация снизу): «Стол №4», «До 6 мест», микрострока-отсылка (напр., *«Лучший вид на экран»* / *«У самого бара»*), кнопка **«Подтвердить выбор»** → Экран 4. Повторный тап по другому столу переключает выбор; тап по выбранному снимает выбор.
- Легенда внизу плана: три маркера «свободен / выбран / занят».

### Экран 4. Контакты и правила («Ваш билет»)

- Шапка: «назад», заголовок **«Ваш билет»**.
- **Сводка брони** — карточка в виде верхней части билета: дата, время, стол, гости. Справа внизу — пунктирная линия отрыва.
- **Форма:**
  - Имя (обязательно) — placeholder «Как к вам обращаться».
  - Телефон (обязательно) — маска `+375 (__) ___-__-__`, валидация беларуского формата.
  - Комментарий (необязательно) — placeholder «Пожелания: стол у экрана, день рождения…».
  - Поля: фон `--bg-card`, обводка 1px `--accent` 30%, фокус — обводка `--accent` 100% + мягкое свечение. Ошибки — подпись красным `--red`, поле подсвечивается.
- **Правила бара** (дословно из stories заведения, оформить списком с орнаментом):
  1. Бронь стола ограничена 2 часами.
  2. Если по истечении 20 минут гости не сообщили о задержке — бронь аннулируется.
- **Кнопка «Забронировать»** → имитация запроса (спиннер 600–900 мс) → Экран 5.

### Экран 5. Успех («Билет»)

- Появление: билет «въезжает» снизу с лёгким масштабированием, затем микро-дрожание «отрыва по перфорации».
- **Билет:** карточка `--bg-card` с перфорацией по бокам и пунктирной линией отрыва между верхней и нижней частью — чистый дизайн-элемент, без QR-кода и без номера брони:
  - Верхняя часть: логотип `ПЕРСОНАЖИ`, строка «КИНОБАР · МИНСК», дата и крупно время сеанса, микроподпись «ВХОД · ADMIT ONE».
  - Линия отрыва (пунктир + полукруглые вырезы по краям).
  - Нижняя часть: имя гостя, место (название стола / барного стула / секретного зала), количество гостей, декоративная иконка-хлопушка.
- Текст под билетом: *«Дорогие зрители, спасибо за бронирование. Ждём вас в „Персонажах“!»*
- Кнопка: **«На главную»** (primary).
- Бронь сохраняется в LocalStorage (раздел 9.4).

## 6. Анимации

Библиотека: **Framer Motion**. Общий принцип: всё плавно, ничего не дёргается, длительности короткие.

- **Переходы между экранами:** fade + сдвиг по вертикали 16–24px, 300 мс, `easeOut`. Назад — зеркально.
- **Появление секций на главной:** staggered fade-in при скролле (`whileInView`, 80–120 мс между элементами).
- **Чипы дат/слотов:** выбор — scale 0.96 → 1 с заливкой, 180 мс.
- **Столы:** hover/tap scale 1.05; выбранный — пульсирующее золотое свечение; занятый при тапе — shake 200 мс.
- **Bottom-sheet:** spring (`stiffness ~300, damping ~30`), свайп вниз закрывает.
- **Кнопки:** заливка 200–250 мс; нажатие scale 0.98.
- **Билет:** вход снизу (spring), затем лёгкое покачивание 400 мс; тосты — fade/slide 250 мс.
- **Прелоадер первого запуска (опционально):** кинохлопушка/логотип с fade, ≤ 1.2s.

`prefers-reduced-motion`: все анимации сводятся к простым fade.

```
  lib/bookingService.js   # getAvailability(), createBooking() — обёртки над моками;

  context/BookingContext.jsx  # состояние воронки: date, time, guests, table
  components/             # TableMap, Table, BottomSheet, Ticket, EventCard, ...
  pages/                  # Home, BookingParams, TableSelect, Confirm, Success
```

- Занятость столов и слотов вычисляется **детерминированно** от даты и слота (например, хеш от `date+time+tableId`), чтобы демо было воспроизводимым при перезагрузке.
- `createBooking()` валидирует, генерирует номер `PRS-XXXX`, пишет в LocalStorage, возвращает объект брони.

## 10. Задел под админ-панель (в демо не входит)

Требования к архитектуре, чтобы админка добавилась без переписывания:

- Весь доступ к данным — только через `bookingService` (мок → будущий REST API / Supabase / Firebase).
- Зарезервирован роут `/admin` (сейчас — заглушка «Админ-панель скоро»).
- Столы, слоты, события — данные, а не захардкоженная разметка: админка сможет их редактировать.
- Будущие возможности: управление столами и залом, список броней (подтверждение/отмена), управление афишей, рабочие часы и длительность слотов, уведомления гостям.

- [ ] Приложение открывается в формате телефона (390×844); на десктопе — в центрированной рамке телефона на тёмном фоне.

## 13. Допущения
